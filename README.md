# コウノトリのつばさ

公開先は **Netlify Free + PayPal** に確定しました。[Netlifyへの配置手順](docs/netlify-setup.md)と`deploy/netlify.env.example`を参照してください。GitHub連携、PostgreSQL、非公開Blobs、毎時の定期処理に対応。試験データは本番データから分離します。

問い合わせフォーム `/contact` と管理者返信 `/support-admin` を追加しています。氏名・住所・電話番号は請求時開示を既定にし、公開APIに値を出しません。[本番公開の準備](docs/netlify-setup.md)と `deploy/production.env.example` を参照してください。

2026年10月17日にエラーになったチャットから復元し、入金後の審査通知・30日後の自動公開・共通表記を追加しました。[引き継ぎ記録](docs/recovery-2026-10-17.md)を参照してください。

審査通知先は `REVIEW_EMAIL` 環境変数へ設定します。通知は管理画面の申請詳細で確認できます。デモではメールを実送信しません。Netlifyでは常駐サーバーを使わず、毎時の予約処理と応答前のメール送信を使います。ローカル版では起動時と毎分の処理も維持しています。

日本国内・18歳以上向けの、個人間の精子提供について対話するための小規模サイト。Next.js / TypeScript、NetlifyではPostgreSQLとBlobs、ローカルではSQLiteで構成。顔面・運動・健康の総合スコアは使いません。メール通知はSMTPで対応し、デモでは実送信せず受信欄で確認できます。

## Windowsでデモを試す

Node.js 24以上を導入し、[デモ用ブランチ](https://github.com/Hamurabidabutsu/-/tree/codex-windows-demo) の **Code → Download ZIP** から取得したZIPを展開して `start-demo.cmd` をダブルクリックすると、必要な部品の導入とブラウザーの起動を自動で行います。[Windows用の手順](docs/windows-demo.md)をご覧ください。PC内のデモは専用の保存先を使い、既存の設定を変更しません。

## 初めてCodexを使う場合

このリポジトリがサイトのソースです。Codexには「検索に体重の範囲を追加して」「登録フォームの説明を変更して」のように、変更したい動作を日本語で指示できます。今回のファイルは作業環境に作成してあります。GitHubへの保存とサイトの一般公開はそれぞれ別の操作です。差分を確認してコミットし、GitHubへ保存する操作はCodexの画面から行えます。

クラウド環境の「公開」は、開発環境を次回も再利用するための操作です。サービスをインターネットへ公開する操作ではありません。今回、依存関係の導入と起動手順を環境設定の下書きに保存しました。設定を保存・公開すると次回の作業に利用できます。ソースをまだGitHubに保存していない場合は、それも保存してください。

画面を動かすにはNode.js 24以上で、以下を実行します。クラウド環境では作業フォルダーは `/workspace/-` です。

```sh
npm ci
cp .env.example .env.local   # 初回のみ。既存設定がある場合は上書きしない
npm run dev
```

デモ環境には架空の提供者3人があり、画面上部の「希望者で試す」「提供者で試す」「管理者で試す」で役割を切り替えられます。実際の人物・検査結果・支払いではありません。登録フォームから新しい架空アカウントを作れば、書類提出・デモ支払い・管理者審査を最初から確認できます。実在の身分証や医療情報をデモへ入れないでください。

Solの高い思考設定で今回の規模は扱えます。文言・見た目の修正は低〜中程度で十分です。決済・権限・削除を変更する際は高程度で実装とテストを行うのが適切です。より強力なモデルは本番前の独立した設計レビューに使う選択肢ですが、必須ではありません。

ゼロから同程度の実装を行う場合の目安は、要件確定後で1〜3時間、ツール出力を含め数万〜十数万トークンです。調査・修正回数に左右され、今回は実際のトークン請求量を取得できていないため、実績値としては扱えません。

## 検証

管理者は `/admin` の「ドナーを手入力登録（無料）」から、新規アカウントを作成するか登録済みドナーを選び、通常登録と同じフォームで入力できます。新規アカウントのメールアドレスは管理者用と別にしてください。本人の同意・本人確認・証明情報を確認し、最後の確認画面で「無料で掲載・更新する」を押します。登録回数に制限はなく、決済は発生しません。履歴は「料金免除」として保存され、既存の支払い記録は維持します。決済処理中の未入金申請は、先に入金状態の確認が必要です。下書き保存では公開プロフィールを変更せず、生年月日の変更は掲載時に反映します。添付した証明書原本は掲載時に削除します。

```sh
npm run typecheck
npm run build
npm test
npm audit --omit=dev
npm start
```

`npm test` は本番ビルドを使用します。先に `npm run build` を実行してください。テスト用サーバーはポート3217・3218・3220・3221、DBと画像は一時フォルダーを使い、デモ/本番データを変更しません。テストでは年齢制限、権限、支払い前の審査拒否、初回/更新審査、差し戻し再提出、証明書削除、開示の撤回、画像チャット、実績の相互確認、退会時の双方の会話削除、計算・分類の境界、旧DB移行、テスト用SMTPによるメール確認・受信通知・通知抑止・送信失敗時の保存を確認します。

## 運用前に必要な設定

開発環境の動作確認は済んでいます。インターネットへの本番公開・実際のPayPal決済はまだ行っていません。

1. 実際の事業内容が決済事業者の利用条件に合うことを確認する。PayPalは実装済みですが、利用可能という判断や事前承認の取得は済んでいません。
2. 運営者名・所在地・電話番号・問い合わせ先、返金条件などを規約/特商法ページへ入れ、草案を確定する。現在は未設定と表示されます。問い合わせ先を架空の値で埋めていません。
3. HTTPSのドメインと永続ディスクがあるNode.jsの実行先を用意する。単一サーバー/単一プロセスを前提とします。保存先が消えるサーバーレス構成へそのまま置かないでください。
4. 安全な環境変数で以下を設定する。秘密値をチャットやGitへ貼り付けないでください。

| 変数 | 本番設定 |
|---|---|
| `APP_MODE` | `live`。デモログイン・架空データを停止 |
| `STORAGE_BACKEND` | Netlifyでは `netlify`。ローカルは `sqlite`とDATA_DIRを指定 |
| `SITE_URL` | 実際のHTTPSのサイトURL |
| `PAYMENT_MODE` | `paypal` |
| `PAYPAL_ENVIRONMENT` | まず `sandbox`、外部検証後に `live` |
| `PAYPAL_WEBHOOK_ID` | 同じRESTアプリで作った署名検証用Webhook ID |
| `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` | 対応するPayPalアプリの認証情報 |
| `MAIL_MODE` | 本番は `smtp`。デモは `preview`（実送信なし） |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` | SMTP接続先・送信者。465はTLS、587等のリモート接続はSTARTTLS必須。秘密値は安全に設定 |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | 初回管理者作成用。パスワード12文字以上。作成後は起動用設定から除去可 |

5. Sandboxで注文作成・承認・売上確定・キャンセル・再確認を検証し、その後に本番へ切り替える。今回の結合テストはデモ決済と決済結果の金額/通貨/申請ID照合までです。外部PayPalとの通信は認証情報が未設定のため未検証です。
6. メール通知を使う場合は、SMTPを設定して実際の所有アドレスで確認メールと受信通知を試す。今回はローカルのSMTPテストサーバーで検証済みですが、外部の配信元・到達率は未検証です。
7. バックアップの有無、保存期間、退会者の削除対応を決める。この実装は自動バックアップを作りません。ホスティング事業者のスナップショットはアプリから削除できないため、保存期間とアクセス制限を設定する必要があります。決済事業者の記録もアプリの退会処理では削除できません。
8. [構成・運用メモ](docs/architecture.md)を確認する。公開前の検索エンジン登録は無効です。運用情報を整えてから `src/app/layout.tsx` のrobots設定を変更してください。

Netlify版は公式のDBとBlobsを使い、無料枠上限で停止する構成です。メールはSMTP提供元を選べます。PayPal決済手数料はホスティング費と別です。

## 学歴データ

指定された「みんなの高校情報」「みんなの大学情報」から、取得したページの当年度の学校・学科と偏差値を `catalog/current.json` に保存しています。初回は高校3件・大学9件の学科です。全国全件の収録ではありません。学科の記載がない高校の値は自動採用せず、未収録は管理者が照合し、値が得られなければ `NoData` にします。

```sh
npm run catalog:import                # 高校の先頭1ページと大学の一覧
npm run catalog:import -- --pages=5   # 必要なら高校の取得範囲を増やす
```

取得後はサーバーを再起動します。過年度は保持しません。大学の同一学部・学科に複数の日程がある場合は最高値を採用します。指定式 `偏差値 × 1.5 + 25` はサービス内の参考値であり、学歴から実際のIQを測定したものではありません。公開画面はWAISと区別せず、共通注記つきの最高値を表示します。継続取得・本番でのデータ再利用については提供元の条件確認が残っています。
